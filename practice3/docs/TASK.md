Практическая работа 3. Сквозная трассировка микросервисов (Distributed Tracing & APM)
Цель: Научиться диагностировать задержки (p95 latency) и сбои (5xx ошибки) в распределенной системе с помощью OpenTelemetry и Jaeger, отслеживая путь HTTP-запроса через цепочку микросервисов и SQL-запросов к PostgreSQL.

Время: 90 минут

Формат сдачи: Файл .pdf со скриншотами трасс из Jaeger UI и краткими ответами на вопросы.

Максимальный балл: 6 баллов.

ЭТАП 0. Подготовка и запуск стенда (15 минут)
Скачайте и распакуйте архив с практической работой:

Bash
cd tracing-lab
Запустите весь микросервисный стек одной командой:

Bash
docker-compose up --build -d
Убедитесь, что все 4 контейнера поднялись и работают корректно:

Bash
docker-compose ps
Должны быть в статусе running: postgres, jaeger, service-b, service-a.

ЭТАП 1. Генерация тестового трафика (15 минут)
Чтобы в системе распределенного наблюдения появились данные, сгенерируйте серию из 20–30 входящих HTTP-запросов к Gateway (service-a).

Команда для генерации трафика (Linux/macOS):
Bash
for i in {1..25}; do 
  echo -n "Request #$i: "
  curl -s http://localhost:4001/api/checkout
  echo ""
  sleep 0.5
done
Команда для Windows (PowerShell):
PowerShell
1..25 | ForEach-Object {
    Write-Host "Request #${_}: " -NoNewline
    Invoke-RestMethod -Uri "http://localhost:4001/api/checkout"
    Start-Sleep -Milliseconds 500
}
Что происходит: Часть запросов вернется с успехом, часть вернет ошибку 500 Internal Server Error, а некоторые запросы будут выполняться заметно дольше обычного (около 2 секунд).

ЭТАП 2. Исследование трасс в Jaeger UI (35 минут)
Откройте веб-интерфейс Jaeger в браузере: http://localhost:16686

В левой панели выберите:

Service: service-a-gateway

Нажмите кнопку Find Traces.

Задание 2.1: Анализ здорового запроса (Happy Path)
Найдите трассу, которая завершилась со статусом 200 OK и минимальным временем выполнения (~100–150 мс).

Кликните на неё и рассмотрите каскад вызовов (Waterfall chart).

Ответьте на вопросы в отчете:

Сколько всего спанов (Spans) содержит эта трасса?

С помощью какого HTTP-заголовка контекст трассировки (traceparent) передался из service-a-gateway в service-b-orders? (Подсказка: раскройте атрибуты HTTP-спана в Jaeger). Само значение поля traceparent не отображается в JaegerUI, самостоятельно найдите способ узнать его значение и опишите использованный способ.

Сколько времени занял непосредственный SQL-запрос SELECT * FROM orders... к PostgreSQL?

Задание 2.2: Поиск узкого места (Bottleneck / Latency Analysis)
Перейдите обратно к списку трасс. Настройте фильтр: Min Duration = 1.5s.

Найдите трассу, время выполнения которой превышает 2 секунды, и откройте её.

Ответьте на вопросы в отчете:

На каком конкретно сервисе и компоненте происходит задержка?

Является ли причиной задержки медленный SQL-запрос к PostgreSQL или обработка кода внутри самого Node.js-приложения? Приведите доказательство из таймлайна спанов.

Задание 2.3: Расследование инцидента (Root Cause Analysis для 500 Error)
В левом меню Jaeger выберите фильтр Limit Results / Error State или найдите трассу, отмеченную красным восклицательным знаком.

Откройте ошибочную трассу.

Ответьте на вопросы в отчете:

Какой сервис сгенерировал ошибку?

Раскройте спан со статусом Error. Какой текст исключения (exception.message) записан в логах спана?

Дошел ли запрос до базы данных PostgreSQL в случае возникновения этой ошибки?

ЭТАП 3. Модификация кода и проверка фикса (15 минут)
Представьте, что вы SRE/DevOps инженер, устраняющий найденную проблему в service-b.

Откройте файл service-b/index.js.

Найдите искусственную ловушку ошибки (isError = Math.random() < 0.2) и отключите её, изменив условие на false.

Перезапустите сервис:

Bash
docker-compose restart service-b
Сгенерируйте ещё 10 запросов через curl и убедитесь в Jaeger UI, что новые трассы перестали содержать красные ошибки.

 FALL-BACK СЦЕНАРИИ (Если что-то не работает)
Проблема: В Jaeger UI не появляются трассы.

Причина: Jaeger еще не готов или неправильно указан порт OTLP.

Решение: Проверьте логи сервисов: docker-compose logs -f jaeger. Убедитесь, что в docker-compose.yml у jaeger открыты порты 4318 (HTTP OTLP) и 16686 (UI).

Проблема: Контейнер service-b падает при старте с ошибкой ECONNREFUSED.

Решение: База данных PostgreSQL еще не успела инициализироваться. Выполните docker-compose restart service-b.
