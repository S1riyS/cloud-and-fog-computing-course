- **Вариант 3 — Network-bound:** Генерация локального HTTP/TCP-трафика между двумя процессами через `iperf3` / `wrk`.

## ЭТАП 0. Подготовка и тестовый скрипт Benchmark (15 минут)

Создайте в вашей рабочей директории файл тестового workload `benchmark.sh` (пример для CPU/Memory):

```bash
#!/bin/bash
# benchmark.sh — универсальный синтетический тест
echo "=== Start Workload ==="
# CPU/Memory Stress (работает через dd, openssl или sysbench)
sysbench cpu --cpu-max-prime=20000 run || openssl speed -evp aes-256-cbc
echo "=== End Workload ==="
```

## ЭТАП 1. Baseline — Запуск на хосте (25 минут)

Запустите скрипт напрямую в вашей ОС (Linux, macOS через Terminal, или Windows WSL2).

### Команды для снятия метрик

1. **Время выполнения:** ``` time ./benchmark.sh ```
2. **Пиковое потребление CPU/RAM:** ``` # В отдельном терминале во время работы benchmark.sh: top -b -n 1 | head -n 20 ```
3. **Подсчет системных вызовов (Syscalls):** ``` strace -c ./benchmark.sh 2> strace_host.txt ```

## ЭТАП 2. Виртуальная машина (QEMU/KVM / VirtualBox / Multipass) (45 минут)

Создайте ВМ с **строго заданными лимитами** (например, 2 vCPU, 2 GB RAM).

### 2.1. Измерение времени старта ВМ

Зафиксируйте время от момента вызова команды запуска до готовности SSH/терминала (Cold Boot Time).

### 2.2. Запуск Workload внутри ВМ

Передайте `benchmark.sh` внутрь ВМ и выполните:

```bash
time ./benchmark.sh
strace -c ./benchmark.sh 2> strace_vm.txt
```

### 2.3. Снятие Thread Dump изнутри ВМ

В момент выполнения `benchmark.sh` снимите Thread/Process dump изнутри гостевой ОС:

```bash
ps -efL > process_dump_vm_inside.txt
```

### FALL-BACK для ВМ (Если VirtualBox/KVM тормозит или не ставится)

Используйте CLI-ВМ `multipass` (работает на Windows, macOS, Linux одинаково):

```bash
# Создание ВМ с вашими лимитами (пример: 2 CPU, 2G RAM)
multipass launch --name lab-vm --cpus 2 --memory 2G
multipass transfer benchmark.sh lab-vm:/home/ubuntu/
multipass exec lab-vm -- bash /home/ubuntu/benchmark.sh
```

## ЭТАП 3. Контейнер (Docker / Podman) (35 минут)

Запустите тот же скрипт в контейнере со **строгим ограничением ресурсов**:

```bash
docker run --rm --cpus="2.0" --memory="2g" -v $(pwd):/app ubuntu:latest bash /app/benchmark.sh
```

### 3.1. Ключевой эксперимент: Видимость процессов с Хоста

Пока внутри контейнера крутится `benchmark.sh`, выполните на **Хосте**:

```bash
# 1. Поиск PID процессов контейнера с ХОСТА:
docker top <CONTAINER_ID>
ps auxf | grep benchmark # Процесс ВИДЕН на хосте!

# 2. Снятие Thread/Process dump процесса контейнера прямо С ХОСТА:
ps -efL | grep benchmark > process_dump_container_from_host.txt
```

*(Сравните это с ВМ: процессы внутри ВМ с хоста видны как один монолитный процесс гипервизора `qemu` или `VirtualBox`).*

### 3.2. Syscalls в контейнере

```bash
docker run --rm --privileged -v $(pwd):/app ubuntu:latest strace -c bash /app/benchmark.sh 2> strace_container.txt
```
